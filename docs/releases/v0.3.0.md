# KeeWebX v0.3.0

New is now the default interface. Open the app from a static host or double-click `index.html` in the web release to use New. Classic remains available through `classic.html`.

- Open multiple vaults, edit entries and groups, manage database settings, and use the browser extension from New.
- Save-and-switch checks pending edits, attachments, and synchronization before opening Classic. Failed saves keep the vault and its edits open for recovery and retry.
- Browser-cache writes are acknowledged only after their transaction commits. Failed or disabled caching no longer presents an uncommitted local copy as safely saved.
- Encrypted recovery preserves protected fields, history, and attachments. Keep an independent KDBX backup outside browser storage.
- Both interfaces remain available offline after the application shell is cached. Updates retain the previous shell if a required asset cannot be downloaded.

The web zip and tar.gz contain New and Classic, their assets, license notices, and a self-host guide. Verify the accompanying SHA-256 checksum before extracting. `next.html`, `classic/index.html`, and the legacy `?ui=classic` selector remain compatible with existing links. New stays the default at the root even after opening Classic.

HTTPS or localhost enables browser features that require a secure context. Direct `file://` use does not register a service worker. Browser and authenticator support determines passkey availability.
