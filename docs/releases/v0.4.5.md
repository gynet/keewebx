# KeeWebX v0.4.5

- Let the browser choose how to reach a passkey when registration transport metadata is unavailable. Verification and unlock no longer send an invented list of authenticator transports. Credential ID, relying-party binding, required user verification and WebAuthn PRF remain enforced.
- Reject an assertion from a different credential before reading its encryption output, with a specific mismatch message. Previous local registration and password recovery remain intact when verification fails.
- Reserve space for remote synchronization notices in Settings on short screens, keeping navigation, local encrypted downloads and remote recovery actions reachable.
- Fit long translated Settings headings, and align provider and multi-vault checks with the current unlock and explicit passkey verification controls.

New remains the default. ZIP/TAR downloads remain available separately for New and deprecated Classic, together with the combined compatibility archive and checksums.
